01무엇을 만들었나

사용자가 말이나 글로 "의자 만들어 줘"처럼 요청하면 AI가 블록 설계도를 만들고, 협동로봇 M0609가 손목 카메라로 흩어진 블록을 찾아 설계대로 조립합니다. 설계는 사람이 화면에서 확인하고 승인한 뒤에만 로봇으로 넘어갑니다.

02담당 역할

  • PL — 일정 · PR 규칙 · 결정 기록을 운영하고, 통합 테스트에서 우선순위를 정했습니다.
  • AI 설계 생성 — LLM이 정해진 JSON 형식으로만 후보 3개를 내고 규칙 검사를 거치게 해, 형식 오류 0건.
  • 설계 DB — 설계를 부모 · 버전으로 잇는 PostgreSQL 구조, 비슷한 설계를 찾아 참고하는 RAG.
  • 웹 화면 — Next.js · three.js 3D 미리보기, 로봇 카메라 화면, 정지 버튼, 로봇 PC와의 MQTT 브리지.
  • YOLO seg 학습 — 라벨링 규칙 수립, 학습 조건 5종 비교 후 최종 모델 선정.

03막혔던 문제와 해결

상황

겹쳐 놓인 블록을 모델이 놓치거나 둘을 하나로 인식했습니다.

원인

라벨링할 때 겹친 블록의 경계를 사람마다 다르게 그려 학습 데이터 기준이 흔들렸습니다.

해결

라벨 규칙을 하나로 정해 다시 라벨링하고, 같은 조건으로 재학습했습니다.

결과

mAP50 0.87 → 0.972. 시연에서 설계대로 조립 11/11.

04끝내지 못한 것

AI 설계 생성은 평균 103초가 걸려 목표인 60초 안에 들지 못했습니다. 검사를 통과한 후보만 남기고 모자란 만큼 다시 만들도록 바꾸면서 시간이 늘었고, 16일 일정에서 기능이 먼저 동작해야 한다고 판단해 생성 전체에 5분 상한을 두는 데서 멈췄습니다. 시간이 더 있었다면 꼭 필요한 규칙만 남기고 완화해 생성 시간과 설계 다양성을 시험했을 것입니다.

05배운 점

  • 모델을 바꾸기 전에 데이터 기준부터 통일해야 결과가 달라집니다.
  • 통신으로 받은 데이터는 지금 실행의 것인지부터 확인해야 합니다. 옛 진행 상태가 남아 화면이 어긋났던 문제를 실행 ID로 걸러 해결했습니다.
